# GLOSSARY (agent adds terms in plain words)
Format: **Term**: plain meaning. Example from this project.

- **Virtual Environment**: An isolated Python installation folder dedicated to a single project, keeping its libraries separate from the rest of your computer. Example: `.venv` created with Python 3.11 for `gharchive-lakehouse`.
- **Rate Limit**: The maximum rate of requests or tokens an API allows before temporarily blocking further calls (returning HTTP 429). Example: Google AI Studio capping Gemini Flash at 15 Requests Per Minute (RPM) and 1,500 Requests Per Day (RPD).
- **.gitignore**: A configuration file telling Git which files and directories should never be tracked or uploaded to GitHub. Example: ignoring `.env` (protecting your secret API keys) and `data/` (preventing multi-gigabyte raw files from polluting git history).
- **actor**: The GitHub user account that triggered the event (contains `login`, `id`, avatar URL). Example: `Boris-Sachet` opening an issue.
- **repo**: The GitHub repository on which the event took place (contains `name` and `id`). Example: `knowmics-lab/oncoreport`.
- **payload**: The inner details payload specific to each event type; for an issue event, it holds the `action` (`opened`, `closed`, `reopened`), `issue` number, title, body, and labels.
- **created_at**: The UTC timestamp in ISO-8601 string format indicating when GitHub recorded the event. Example: `2024-06-10T15:00:00Z`.
- **Ground Truth**: Real, observed, trustworthy target data directly from the source used to train and evaluate models. Example: Real issue labels (`bug`, `enhancement`) added by project authors on GitHub.
- **Silver Labels**: Labels automatically inferred or generated by an external AI model (e.g. Gemini) rather than verified ground truth.
- **Manifest**: An audit log / inventory catalog that lists all downloaded or ingested files, their byte sizes, and processing statuses. Example: `data/raw/manifest.json`.
- **Stream Truncation**: When a network stream cuts off mid-transfer before sending the complete file or EOF marker. In gzip, this produces an incomplete file that crashes standard unzippers unless explicitly validated.
- **Parquet**: A columnar binary storage format designed for analytical queries; stores values column-by-column rather than row-by-row, enabling high compression and fast filtering. Example: saving cleaned GitHub events into `data/clean/*.parquet`.
- **Partition**: Organizing a dataset into directory hierarchies based on column values (such as date or event type) so downstream tools only read the folders they need instead of scanning the full dataset. Example: `data/clean/event_date=2024-06-10/event_type=IssuesEvent/`.
- **Idempotent**: An operation that gives the exact same result no matter how many times you run it with the same inputs, preventing duplicate records or corrupted state. Example: running the ingestion or cleaning script twice overwrites or skips identical data cleanly.
- **Reconciliation**: A mathematical audit check verifying that the number of incoming records equals the number of outgoing records plus every dropped record (`rows_read == rows_kept + sum(dropped)`). Example: `DQCounter.assert_reconciles()`.
- **Fixture**: Hand-crafted, predictable sample data used in unit tests to verify that code handles valid data, edge cases, and corrupt records correctly. Example: `tests/fixtures/sample_events.jsonl`.
- **Reason Code**: A standardized text token recording why a specific record was rejected, ensuring no data is dropped silently. Example: `DROP_BOT = "BOT_ACTOR"` in `src/transform/reasons.py`.
- **Star Schema**: A relational warehouse design with a central fact table surrounded by dimension tables, optimizing analytical queries (OLAP) and simplifying joins. Example: `fact_events` surrounded by `dim_repo`, `dim_actor`, `dim_event_type`, and `dim_date`.
- **Fact Table**: A table containing quantitative measurements, transactional occurrences, or event records with a defined grain. Example: `fact_events` where each row represents one distinct GitHub event.
- **Dimension Table**: A table containing descriptive, contextual attributes that filter, group, or categorize fact measurements. Example: `dim_repo` storing `repo_name` and `repo_owner`.
- **Primary Key (PK)**: A column or set of columns uniquely identifying every individual record in a table. Example: `event_id` in `fact_events`.
- **Foreign Key (FK)**: A column in a table referencing the primary key of another table, guaranteeing referential integrity. Example: `repo_key` in `fact_events` pointing to `dim_repo.repo_key`.
- **Surrogate Key**: An artificial, system-generated integer key assigned to dimension records, decoupling the warehouse from external natural IDs. Example: `repo_key` (1, 2, 3...) in `dim_repo`.

- **Cross-Engine Reconciliation**: Auditing identical data aggregations across two completely independent query engines (e.g. DuckDB and PySpark) to guarantee mathematical consistency and catch engine-specific bugs or dialect discrepancies. Example: `tests/test_spark_vs_duckdb.py` proving exact match across all 69,328 repos.
- **Inverted Index**: An information retrieval data structure mapping each unique word to a postings list of document IDs and word frequencies, allowing sub-millisecond keyword lookups instead of scanning every text document. Example: `InvertedIndex` in `src/ir/index.py`.
- **BM25 (Best Matching 25)**: A state-of-the-art probabilistic ranking function that scores document relevance based on term frequency saturation and document length penalization. Example: `BM25Ranker` in `src/ir/bm25.py`.
- **Dirichlet Prior Smoothing**: A Bayesian language modeling technique that blends document word probabilities with the background corpus collection frequency using pseudo-counts (&mu;=2000), preventing zero-probability errors on unseen words. Example: `LanguageModelRanker` in `src/ir/lm.py`.
- **Multinomial Naive Bayes**: A probabilistic classifier that applies Bayes' theorem under the assumption that all words in a document are conditionally independent given the class label. Example: `MultinomialNaiveBayes` in `src/ir/naive_bayes.py`.
- **1D-CNN (1D Convolutional Neural Network)**: A deep learning model using 1-dimensional sliding filters over token embeddings to capture local phrase patterns (n-grams) for text classification. Example: `IssueCNN` in `src/ml/model.py`.
- **Schema Drift**: Unplanned changes over time to the structure, column names, data types, or distribution of an upstream data source. Example: comparing GH Archive fields in 2024 vs 2026 in `docs/SCHEMA_DRIFT.md`.
